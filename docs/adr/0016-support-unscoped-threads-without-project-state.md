# Support Unscoped Threads Without Project State

Accepted: the product supports Unscoped Threads that do not require a Project folder, alongside Project Threads. An Unscoped Thread has its own model context, may use files attached directly to it, may recall relevant user-level Long-term Memory, may run Investment Reflection within the same isolation boundary, and may write Outputs to a user-selected Unscoped Output Location, but it has no implicit access to any Project Context, Project Memory, project materials, Outputs, or project files. The output destination does not authorize scanning unrelated files. Provenance from a Long-term Memory entry back to a Project does not grant access to that Project. Conversion to a Project Thread requires user-initiated Thread Scope Elevation; after confirmation it inherits the target Project's standard policy, with attachment import as the only separate choice and no Thread-level access matrix. The Agent cannot initiate or infer elevation. This preserves a Codex-like low-friction conversation path while accepting a second thread scope that must keep project data isolated.
