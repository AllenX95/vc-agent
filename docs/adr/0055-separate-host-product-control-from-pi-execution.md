# Separate Host Product Control From Pi Execution

Accepted: the Electron Host is vc-agent's product control plane and owns product policy, Operational State, Thread Trajectory, authorization, workflow coordination, and final product-state commits. Lazy Project or Unscoped Agent Workers own only active Pi runtime resources, Provider execution, and the Physical Model Context required for their isolated sessions; the Renderer is a view and command surface rather than a direct filesystem, credential, Provider, or Pi client.

Thread Trajectory and Pi session persistence are deliberately separate. Thread Trajectory is authoritative for user-visible history, audit, deletion, Dream eligibility, and provenance, while a Pi session is authoritative only for its Physical Model Context and remains behind a versioned Pi Adapter. Product permissions, Memory eligibility, workflow state, and Project truth must never be inferred solely from Pi session internals.

Model-invoked product capabilities cross a Host Capability Gateway before execution or final commit. Approved Pi Extensions are the explicit exception: as Trusted Worker Code they may exercise Agent Worker process authority outside the Gateway, but they still cannot authoritatively commit Host-owned Operational State, Memory, authorization, or other durable product semantics. Pi uses an app-controlled ResourceLoader, settings, model registry, and runtime credentials rather than default project or global discovery. This adds structured IPC, correlation ids, and crash reconciliation, but prevents SDK schema changes, arbitrary discovered resources, or a failed Agent Worker from owning the product's durable semantics.
