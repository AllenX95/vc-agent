# Isolate Local Executable Jobs From Host And Agent Workers

Accepted: Electron Main never loads third-party executable code, and Project or Unscoped Agent Workers do not load OCR, local document models, Office automation, arbitrary Skill dependencies, or Shell jobs in process. Pinned app-owned parsers, renderers, ordinary PaddleOCR, and local OvisOCR2 complex-page parsing run in a bounded on-demand Utility Worker Pool, while User-supplied Skill scripts, Office COM automation, Shell commands, and dependency installers run as supervised short-lived Isolated Job Processes.

A generic Host-owned Utility Job Runner applies authorization, scoped inputs, bounded output capture, cancellation, sanitization, staging, and final commit for both tiers. Approved Pi Extensions are the narrow exception because they require Pi runtime hooks and therefore execute inside the Agent Worker as Trusted Worker Code. Bundled Extensions and later additions enter that inventory only as exact, pinned artifacts that have passed Extension Admission Review and explicit User approval; changed artifacts lose approval. Extension approval and enablement are separate User actions. Full Access suppresses applicable Host-mediated tool confirmations but never admits an unreviewed Extension, grants Worker-level trust implicitly, moves executable work into Electron Main, removes process isolation, or bypasses Host validation of requested durable product-state commits. This adds process supervision and staging while preventing one local dependency or arbitrary script failure from corrupting product state or every active Pi session.
