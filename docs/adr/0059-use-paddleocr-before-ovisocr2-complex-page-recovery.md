# Use PaddleOCR Before OvisOCR2 Complex Page Recovery

Accepted: the Personal Build uses one fixed local page-recovery chain behind `material_parse`: preserve usable PyMuPDF native content; run ordinary PaddleOCR when native text is missing or unreliable; then run OvisOCR2 only when ordinary OCR is missing, unreliable, or structurally insufficient for complex layout, tables, formulas, visual regions, or reading order. PP-StructureV3 is removed from the active first-release chain. This supersedes ADR-0038 and amends ADR-0039.

The stages are not interchangeable providers or a user-selectable fallback chain. The Host applies deterministic page-quality routing, records every invoked stage and pinned version, and retains the best usable earlier-stage result. OvisOCR2 uses deterministic decoding and bounded resources, and its generated Markdown must pass truncation, repetition, table/formula-structure, and source-page validation before becoming the preferred representation. Failure to recover complex structure produces `complex parse unavailable` while preserving usable text; `OCR unavailable` is reserved for pages from which no stage recovered usable text.

PaddleOCR and OvisOCR2 remain local Utility Worker jobs and never load into Electron Main or an Agent Worker. Local OvisOCR2 inference does not require a Model Profile and does not create an Agent Turn or contact a Provider. Its CPU path may be exposed when validated by the pinned runtime, but availability is not represented as adequate throughput; Environment Doctor reports the validated CPU or GPU execution path. The runtimes and weights are pinned, installed under Access Mode policy, and not embedded in the main installer.
