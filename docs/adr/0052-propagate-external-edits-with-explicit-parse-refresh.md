# Propagate External Edits With Explicit Parse Refresh

Accepted: vc-agent remains single-instance while transparent Project and Memory files stay externally editable. Stable external changes update lightweight inventory and hashes without an LLM or eager parsing. Project Context and Memory authoritative-file edits rebuild deterministic mirrors or recall indexes; malformed user content is preserved with warnings. An Active Turn keeps the input versions it already consumed and receives no implicit mid-turn steering, while freshness-dependent downstream results become stale.

When a changed Material with a prior Parsed Material Artifact is next needed, parsing pauses for an explicit Parse Refresh Choice under both Access Modes. `Create New Parse Version` is the recommended default and preserves the old artifact. `Replace Previous Parse` validates the new parse before removing the selected old parsed content; historical Outputs are not rewritten, and retained provenance marks removed content `source unavailable`. Failed or canceled refresh never silently discloses stale content and never deletes the old artifact.

Host-managed state and cognitive writes compare the authoritative version read during preparation with the current target. A mismatch creates a Stale Write that requires regeneration or revalidation and cannot be resolved by automatic LLM merging, even under Full Access. Generic Outputs and external-tool side effects retain their existing collision and Unknown Tool Outcome policies. This preserves direct file editability and user control over parse retention at the cost of explicit stale states and occasional task-time prompts.
