# Allow Visible Automatic Thread Compaction

Accepted: before every Provider request, the Host projects the request against the active Model's usable context budget. It first retires eligible large tool payloads to Context References and then automatically invokes Thread Compaction, without User confirmation, when retained prior conversation still prevents the current task from fitting. Compaction may occur before a new Turn or between model steps of one Active Turn, preserves current work state and stable references, remains visible as a runtime event, and is never promoted automatically into Project Context or any Memory.

After compaction, current User instructions, explicit task inputs, and Explicit Memory Recall take priority over optional or automatic recall. If those current inputs are themselves too large, vc-agent uses progressive retrieval or visibly requires a narrower scope instead of repeatedly compacting or replacing unprocessed current content with a model-generated summary. This keeps long Codex-like conversations usable and token-bounded while accepting lossy removal of superseded conversational detail.

Compaction uses the effective Model Profile of the Thread or current workflow stage whose context is being compacted. The first release has no separate Compaction Task Model Assignment and never selects a cheaper Model or another Provider automatically; a cross-Provider Profile can compact an existing Thread only after the User has authorized Cross-Provider Thread Continuation. Compaction usage is reported separately, and a failed compaction follows normal Provider Failure handling without fallback.
